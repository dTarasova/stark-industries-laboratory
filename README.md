# Лаборатория — №01

Реализован локальный каркас React/TypeScript: просмотр `/`, пульт `/control`, сервер Node.js 24 и SQLite. Пульт меняет только общий этап с явным подтверждением. EDITH не участвует в авторизации. Опрос сервера каждые 2 секунды; страницы не меняют состояние. Конфликт одновременных изменений требует нового подтверждения. Сессия ведущей живёт 12 часов, перезапуск сервера требует повторного входа.

## Запуск

Из этой папки: `npm ci`, затем `npm run build`. Задайте переменную окружения `ADMIN_PASSWORD` (от 16 символов, отдельный случайный пароль), затем `npm start`. Откройте `http://localhost:3000`. Для разработки: сервер плюс `npm run dev` в другом окне. Проверки: `npm test`, `npm run build`.

## Размещение и памятная копия

Технический вариант реализации: один Node.js 24 процесс и постоянный диск SQLite. Публикация пока не выполнена; конкретный провайдер и стоимость не утверждены. Бесплатный сервис с временным диском не подходит. Для публикации нужны постоянный каталог `data`, HTTPS, переменные `ADMIN_PASSWORD`, `NODE_ENV=production`, `PORT`. Повторная публикация: сохранить `data`, установить зависимости `npm ci`, собрать `npm run build`, перезапустить `npm start`. Не запускать несколько независимых экземпляров с разными базами.

Цель хранения — минимум до 29 ноября 2027. Это требование, а не гарантия ещё не выбранного хостинга. Памятная копия: остановить сервер, скопировать `data/mission.sqlite` вместе с исходниками, lock-файлом и `dist`, затем снова запустить. Копию можно открыть тем же сервером локально; пароль задать новый. Регулярно сохранять резерв вне диска хостинга. Для будущих медиа потребуется добавить их в резерв.

Перед размещением за обратным прокси нужно настроить доверенное определение IP: сейчас лимит входа действует на адрес прямого соединения, за прокси он может оказаться общим. Не принимать произвольный X-Forwarded-For. Это ограничение необходимо устранить при выборе платформы.

## Docker — сборка и запуск без локального Node.js

Нужен работающий Docker Desktop с Linux-контейнерами. Из `website/laboratory`:

1. Если `.env` ещё нет, скопируйте `.env.example` в `.env`. Существующий файл не перезаписывайте.
2. Заполните `ADMIN_PASSWORD` отдельным паролем от 16 символов. Если пароль содержит `$` или `#`, заключите значение в одинарные кавычки.
3. Выполните `docker compose up --build -d`.
4. Откройте `http://localhost:3000`, пульт — `http://localhost:3000/control`.

Node.js, зависимости, проверка типов, сборка и тест сервера выполняются внутри Docker. Финальный образ содержит только Node.js, сервер и собранный интерфейс; пароль в образ не копируется. Compose читает `.env` и передаёт пароль при запуске.

Логи: `docker compose logs --tail=100 laboratory`. Остановка: `docker compose down`. Обновление: `docker compose up --build -d`. Состояние хранится в именованном томе `mission-data` и переживает пересоздание контейнера. Команда `docker compose down -v` удалит этот том вместе с миссией.

По умолчанию сайт доступен только на этом компьютере. Для размещения нужен HTTPS перед контейнером и `NODE_ENV=production` в `.env`: это включает защищённую cookie пульта. Локальный HTTP использует `development`, иначе браузер не сможет сохранить вход. Docker сам по себе не предоставляет хостинг и не гарантирует год доступности.

Памятная копия базы из Docker (папку `backup` предварительно создать):

```powershell
docker compose stop laboratory
docker compose cp laboratory:/app/data/mission.sqlite ./backup/mission.sqlite
docker compose start laboratory
```

Храните копию вне Docker вместе с исходниками и lock-файлом. Для восстановления остановите контейнер и скопируйте базу обратно через `docker compose cp ./backup/mission.sqlite laboratory:/app/data/mission.sqlite`, затем запустите его. Не выполняйте `down` между остановкой и копированием: для `cp` нужен существующий контейнер.

## Первый тест «Нового элемента»

Из каталога лаборатории выполните `npm ci` и `npm run dev`. Откройте в Chrome `http://127.0.0.1:5173/prototype/` (если порт занят, возьмите адрес из вывода Vite). Сервер миссии, пароль и EDITH для этого запуска не нужны. Условия и образец выдаются в чате.

Попытка и геометрия открытого элемента сохраняются в текущей вкладке, включая перезагрузку. Сброс восстанавливает исходный макет, а модель остаётся доступной отдельной кнопкой. Это хранилище самостоятельного теста. В общей миссии сохранение должно работать между устройствами через сервер.

При запуске через Docker выполните `docker compose up --build -d` и откройте `http://localhost:3000/prototype/`. Если в `.env` задан `HOST_PORT`, используйте этот порт. Страница прототипа открывается напрямую.
