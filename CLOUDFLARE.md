# Cloudflare Workers + D1

Подготовлена полноценная версия лаборатории для Cloudflare: React и `/api/*` работают на одном домене Worker, общая миссия и вход ведущей хранятся в D1. Свой сервер, Docker и Tunnel не нужны. Это **Workers**, а не статический проект Pages.

Серверная логика общая для обоих вариантов: `api.mjs`. `server.mjs` оставлен для Node.js/SQLite и Docker; `worker.mjs` использует адаптер `cloudflare-db.mjs`, авторизацию в D1 и файлы из `dist`.

## Разовая настройка

Команды выполнять из папки `website/laboratory`. Если отдельный Git-репозиторий начинается прямо с этой папки, она уже является его корнем.

1. Установите зависимости и войдите в Cloudflare:

   ```powershell
   npm ci
   npm run cf:login
   ```

2. Создайте базу:

   ```powershell
   npm run cf:db:create
   ```

   Из результата скопируйте `database_id` в существующую запись `d1_databases` в `wrangler.jsonc`, заменив `00000000-0000-0000-0000-000000000000`. Сохраните имя привязки **`DB`** и `migrations_dir`. Если Wrangler предлагает автоматически добавить ещё одну привязку, откажитесь: запись `DB` уже есть. Если база уже создана, используйте её ID вместо повторного создания.

   База D1 создаётся отдельно от локального `data/mission.sqlite`: облачная миссия начинается с нуля. Текущий файл SQLite остаётся на месте.

3. Проверьте поле `name` в `wrangler.jsonc`: оно должно совпадать с именем существующего **Worker**, который хотите обновлять. Сейчас указано `stark-industries-laboratory`.

4. В Cloudflare откройте этот Worker → **Settings → Variables and Secrets**. Добавьте как **Secret**:

   | Имя | Значение |
   |---|---|
   | `ADMIN_PASSWORD` | Ваш пароль пульта, минимум 16 символов |
   | `EDITH_CODE` | Ваш код EDITH |

   Это переменные работающего Worker, а не только настройки Build. Не добавляйте префикс `VITE_`, не записывайте пароли в `wrangler.jsonc` или Git. При первом создании Worker секреты можно задать после первого деплоя; до этого API вернёт понятный ответ 503. Через терминал альтернативно: `npx --yes wrangler@4 secret put ADMIN_PASSWORD` и `npx --yes wrangler@4 secret put EDITH_CODE` — значения вводятся интерактивно.

## Публикация из Git

В существующем проекте **Workers Builds** укажите:

| Поле | Значение |
|---|---|
| Root directory | `.` для отдельного репозитория лаборатории; иначе `website/laboratory` |
| Build command | `npm run build` |
| Deploy command | `npm run cf:deploy` |

Команда deploy сначала применяет миграции D1, затем публикует Worker вместе с `dist`. Нужен build API token с правами публикации Workers и **D1 Edit** для применения миграций. Если стандартный токен сборки не позволяет применять миграции, выполните `npm run cf:migrate` локально после `cf:login`, а Deploy command замените на `npx --yes wrangler@4 deploy`. В таком варианте новые миграции тоже применяются отдельно перед публикацией.

Закоммитьте изменения, включая настоящий ID D1, и отправьте в подключённую ветку. Секреты остаются в Cloudflare. Сам ID базы не является паролем. Настройки Pages, output directory и `npm start` для этого варианта не используются.

Публикация вручную вместо Git:

```powershell
npm run build
npm run cf:deploy
```

Wrangler 4 запускается через `npx` и скачивается при первом использовании; дополнительно устанавливать его глобально не нужно. В этой рабочей среде скачивание из npm недоступно, поэтому запуск настоящего Workers runtime и удалённый деплой здесь не проверены.

## Проверка опубликованного сайта

1. Откройте адрес `https://<worker>.<account>.workers.dev/api/mission`: должен вернуться JSON с `stage`, `version` и остальными данными миссии.
2. Откройте `/control`, войдите в пульт. Откройте `/` на другом устройстве и проверьте синхронизацию этапа.
3. Проверьте EDITH, завершение элемента, запуск защиты, временные линии, восстановление и финал. Используйте тестовую миссию, затем сбросьте её в пульте.
4. Проверьте обновление страницы по прямым ссылкам `/archive`, `/development`, `/timelines/`, `/clean-slate`, `/battle-with-ultron`.
5. Повторно опубликуйте Worker: прогресс и действующая сессия должны сохраниться. Смена `ADMIN_PASSWORD` отзывает старые сессии.

API никогда не отдаётся через SPA fallback: маршруты `/api/*` идут сначала в Worker, ответы не кешируются. Не настраивайте Cache Everything для API. Пароли и хеши сессий не входят в публичное состояние миссии. Не подключайте эту же D1 к публичным preview-развёртываниям, которые могут менять праздничную миссию; используйте отдельную тестовую базу.

## Локальная проверка Workers

Скопируйте `.dev.vars.example` в `.dev.vars`, только если своего файла ещё нет, и укажите тестовые пароли. Не используйте реальные секреты для тестов. Затем:

```powershell
npm run cf:dev
```

Команда собирает интерфейс, применяет миграции к **локальной** D1 и запускает `wrangler dev`. Локальные данные лежат в игнорируемой `.wrangler/`; удалённая база не меняется. По HTTP локально cookie без Secure; опубликованный HTTPS-сайт выдаёт Secure-cookie. `.dev.vars` не загружается в Cloudflare автоматически.

Проверки без сети: `npm run cf:test` — API Worker с асинхронным интерфейсом D1 и настоящим SQLite; `npm test` — также существующие проверки Node.js; `npm run build` — типы и сборка интерфейса. Тестовый адаптер не заменяет проверку в `wrangler dev` и по публичному адресу.

## Если что-то не работает

- **503 / сервер не настроен**: проверьте привязку `DB` и runtime-секрет `ADMIN_PASSWORD` длиной от 16 символов.
- **500 / сервис недоступен**: проверьте ID базы, примените `npm run cf:migrate`. Миграции создают таблицы миссии и авторизации; они не запускаются на каждый запрос.
- **Ошибка авторизации миграций в Builds**: выдайте build-токену D1 Edit либо применяйте миграции локально, как описано выше.
- **По `/api/mission` приходит HTML или пустой ответ**: проверьте, что открываете Worker с новой версией, а не прежний статический Pages-проект.
- **Пульт не входит после смены пароля**: войдите заново; сессии действуют 12 часов и привязаны к текущему паролю.
- **429 при входе**: после пяти неверных попыток адрес блокируется на 15 минут; другие IP не блокируются.

D1 хранит данные независимо от версий Worker. Для резерва: `npx --yes wrangler@4 d1 export DB --remote --output=backup/cloudflare.sql` (сначала создайте папку `backup`). Экспорт содержит хеши сессий; не публикуйте его и не добавляйте в Git. Откат кода Worker не откатывает базу.
