# Публикация через Cloudflare Tunnel

Подготовлен вариант: HTTPS-домен Cloudflare → Tunnel → Docker → Node.js 24 и SQLite. База остаётся в томе `mission-data`. Компьютер или сервер с Docker должен постоянно работать и иметь интернет. Это не размещение приложения в Workers/Pages: простая загрузка `dist` оставит сайт без API и сохранения миссии. Публикация и выбор домена ещё не выполнены.

## Настройка

1. Подготовьте домен в своём аккаунте Cloudflare и постоянно работающий Docker-хост. Из `website/laboratory` скопируйте `.env.example` в `.env`, только если `.env` ещё нет. Заполните `ADMIN_PASSWORD` (16+ символов), `EDITH_CODE` и затем `CLOUDFLARE_TUNNEL_TOKEN`. Секреты не отправляйте в репозиторий. Существующие значения сохраняйте.
2. В Cloudflare создайте remotely-managed Cloudflare Tunnel, выберите Docker и возьмите значение токена из предложенной команды. Саму команду запускать не нужно: соединитель запускается через Compose ниже.
3. Добавьте published application route: выбранный hostname, тип HTTP, service URL `http://laboratory:3000`. Не используйте localhost: соединитель работает в отдельном контейнере. Оставьте исходный Host без переопределения, чтобы проверка Origin у API совпадала с публичным доменом.
4. Включите перенаправление посетителей на HTTPS (Always Use HTTPS). Не задавайте Cache Everything для приложения; если на домене уже есть правила кеширования, добавьте bypass для `/api/*`. Не включайте преобразование, удаляющее заголовки IP посетителя.
5. Запустите:

```powershell
docker compose -f compose.yaml -f compose.cloudflare.yaml up --build -d
docker compose -f compose.yaml -f compose.cloudflare.yaml logs --tail=100 cloudflared laboratory
```

Профиль принудительно включает production и Secure-cookie. Пульт проверяйте через публичный HTTPS-домен. HTTP на localhost оставлен только для диагностики и не подходит для входа в этом режиме. Порт 3000 привязан к loopback; пробрасывать его на роутере не нужно.

Внутренняя сеть туннеля использует `172.30.28.0/24`, адрес соединителя — `172.30.28.2`. Если эта подсеть занята, согласованно замените subnet, ipv4_address и TRUSTED_PROXY_IP в `compose.cloudflare.yaml`. Сервер доверяет CF-Connecting-IP только от этого адреса; прямой запрос не может менять ключ ограничения входа произвольным заголовком. Не подключайте посторонние контейнеры к этой сети.

## Проверка перед праздником

- Откройте `/`, `/archive`, `/development`, `/clean-slate`, `/battle-with-ultron` и `/control` по HTTPS; проверьте обновление страницы по прямой ссылке.
- Войдите в пульт, откройте сайт на телефоне через мобильную сеть, измените этап и проверьте синхронизацию. Проверьте код EDITH и сброс тестовой миссии.
- Пересоздайте контейнеры той же командой запуска: состояние должно сохраниться, вход ведущей потребуется заново.
- Проверьте, что без входа команды ведущей запрещены. Пять неверных входов временно блокируют адрес посетителя, а не всех пользователей туннеля.

Обновление: повторите команду запуска с `--build`; для обновления соединителя сначала выполните `docker compose -f compose.yaml -f compose.cloudflare.yaml pull cloudflared`. Образ использует latest; перед праздником зафиксируйте проверенный digest и не обновляйте его без повторной проверки.

Остановка: `docker compose -f compose.yaml -f compose.cloudflare.yaml down`. Не добавляйте `-v`: это удаляет базу. Резервирование и восстановление описаны в README; используйте оба `-f` и там. Запускайте команды из той же папки и не меняйте имя Compose-проекта, иначе получится другой том. Сохраните резерв за пределами Docker-хоста. Tunnel не заменяет резерв и не гарантирует доступность до 29 ноября 2027.

При 502 проверьте готовность laboratory и service URL; при 1033 — токен и соединение cloudflared. При отклонении POST проверьте, что Host не переопределён. Не публикуйте вывод `docker compose config`: он содержит значения секретов.

Официальные инструкции: [создание Tunnel](https://developers.cloudflare.com/tunnel/get-started/), [параметры соединителя](https://developers.cloudflare.com/tunnel/reference/run-parameters/), [заголовки IP](https://developers.cloudflare.com/fundamentals/reference/http-headers/).
